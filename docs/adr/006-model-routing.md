# ADR 006: Route routine implementation to a faster model

Status: accepted by the repository owner on 2026-10-18. Evaluated with
`specify-cli` 1.2.1 and current Claude Code subagent/skill docs.

## Context

Planning, clarification, and architecture benefit most from the strongest
model. Many implementation tasks are fully specified by then (follow an
existing pattern in named files) and can run on a cheaper, faster model.
List prices (per million input/output tokens, Claude API, 2026-10): Fable 5.1
$10/$50, Opus 5.5 $4/$20, Sonnet 5.5 $2/$10, Haiku 5.5 $0.10/$0.50.

Options:

1. **Spec Kit workflows.** `workflow.yml` steps accept `model:` (and a
   workflow-level default), dispatched as `claude -p <prompt> --model <m>`.
   Each step is a separate headless process with no shared conversation;
   `/speckit-clarify` cannot ask the user anything; permissions need
   `SPECKIT_INTEGRATION_CLAUDE_EXTRA_ARGS`. The routing grain is a whole
   command, so all of `/speckit-implement` runs on one model.
2. **Model in generated skill frontmatter** (`model:` in
   `.claude/skills/speckit-*/SKILL.md`). Those files are generated by
   `specify init` per product and rewritten on upgrade; same per-command grain.
3. **Claude Code subagent for delegated tasks.** `.claude/agents/*.md` accepts
   `model` and `effort`; the main session delegates during implementation.
   Task-level grain, interactive flow preserved.

## Decision

Adopt option 3. Ship `.claude/agents/speckit-implementer.md` (`sonnet`, effort
`medium`, no commit/spec/status rights). `/speckit-tasks` tags fully specified
tasks `[ROUTINE]` (tasks override). The main session (`opus` by default) keeps
planning, untagged tasks, review, verification, commits, and GATE handoffs.
Model aliases, not dated IDs, so the template tracks current models. Untagged
is the default, so a missing tag costs money, never quality.

Option 1 stays available for a fully unattended run of an already clarified
feature; it is not part of the default flow.

Verification: `scripts/check-model-routing.mjs` (`pnpm models:check`) reads
Claude Code's local transcripts. The main session is in
`~/.claude/projects/<cwd>/<session>.jsonl`; subagents are in
`<session>/subagents/agent-*.jsonl` with `agentType` in `*.meta.json`. It
reports the models that actually answered, not a model's self-description,
and fails on mismatch. It depends on Claude Code's transcript layout (observed
2026-10-18), which is not a documented interface: if the layout changes, the
check exits 2 rather than passing falsely.

## Consequences

Routine coding runs at about half the Opus price, faster, with less main-context
growth. Costs: delegation and review overhead per batch, prompt caches are
per model (no reuse across tiers), and tagging quality depends on the planner.
Cost-optimization guidance suggests comparing one strong model at lower effort
before assuming a cascade saves money; measure on a real product and adjust
(for example `effort: high`, or `inherit` to disable routing). The subagent file
is Claude Code-specific; other agents ignore it and follow AGENTS.md's fallback.
